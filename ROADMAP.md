# План развития WireWizardGUI

Пункты расположены в рекомендуемом порядке. К следующему крупному этапу лучше
переходить после выполнения критериев готовности предыдущего.

## Готово

- [x] Русский интерфейс, русские пользовательские сообщения и GUI-smoke-тесты.
- [x] Portable и устанавливаемые сборки для Windows и Ubuntu.
- [x] Автоматическая сборка релизных артефактов в GitHub Actions.
- [x] Надёжный разбор стрелок и параллельных групп WireViz в редакторе маршрутов.
- [x] Единый канонический набор исходников в пакете `wirewizard_gui/`.
- [x] Защита несохранённых изменений и атомарное сохранение JSON-проектов.
- [x] Безопасное переименование и удаление компонентов со связанными маршрутами.
- [x] Структурированная панель ошибок и предупреждений с навигацией.
- [x] Масштабируемый SVG-предпросмотр с экспортом и подсветкой компонентов.

## Этап 1. Исправления и защита данных

### 1.1. Надёжный разбор маршрутов — выполнено

- [x] Поддержаны стрелки WireViz `->`, `-->` и `<=>` без повреждения строки.
- [x] Параллельные группы сохраняются при открытии в табличном редакторе.
- [x] Сигнал в мастере шлейфа подключается один раз.

Импорт, редактирование и повторный экспорт покрыты доменными, GUI- и
интеграционными тестами с закреплённой версией WireViz.

### 1.2. Один канонический набор исходников — выполнено

- [x] Удалены зеркальные каталоги `domain/`, `services/`, `ui/` в корне.
- [x] Реализация находится только в пакете `wirewizard_gui/`; корневой `app.py`
  остался тонким совместимым запускателем.

Структурный тест запрещает legacy-импорты и повторное появление зеркал; тесты,
wheel и PyInstaller используют один канонический пакет.

### 1.3. Защита несохранённой работы — выполнено

- [x] Состояние «проект изменён» отслеживается и показывается `*` в заголовке окна.
- [x] Перед созданием, открытием, импортом и закрытием запрашивается подтверждение.
- [x] Добавлены горячие клавиши `Ctrl+N`, `Ctrl+O`, `Ctrl+S`, `Ctrl+Shift+S`.
- [x] Проект сохраняется атомарно через временный файл и замену исходного.

Диалоги «Сохранить / Не сохранять / Отмена», откат неудачного открытия и ошибки
атомарной записи покрыты GUI- и сервисными тестами. Ошибка записи не повреждает
существующий файл.

### 1.4. Безопасное переименование и удаление — выполнено

- [x] При переименовании компонента обновляются точные ссылки в соединениях.
- [x] Перед удалением показываются зависимые строки и предлагается удалить их
  вместе с компонентом либо отменить операцию.
- [x] Обозначения вроде `X1` и `X10` не смешиваются.

Доменные и GUI-тесты проверяют точное переименование, отмену удаления и удаление
зависимых строк. После подтверждённой операции валидатор не находит потерянных
ссылок.

## Этап 2. Ежедневное удобство

### 2.1. Панель проблем — выполнено

- [x] Ошибки и предупреждения разделены по уровню серьёзности.
- [x] Для проблемы показываются компонент и номер строки соединения.
- [x] Двойной щелчок открывает компонент либо строку соединения.
- [x] Ошибки блокируют WireViz и предпросмотр, предупреждения — нет.

Структурированные проблемы доступны домену и GUI; тесты проверяют уровни,
источник, навигацию и блокировку внешнего запуска.

### 2.2. Улучшенный SVG-предпросмотр — выполнено

- [x] Добавлены масштабирование колёсиком, панорамирование и «Вписать».
- [x] Добавлены кнопки сохранения SVG и PNG.
- [x] Выбранный компонент подсвечивается, если его обозначение найдено в SVG.

GUI-тесты проверяют zoom/fit, экспорт обоих форматов и подсветку выбранного
designator без изменения исходной модели проекта.

### 2.3. Фоновое построение

- [x] WireViz выполняется вне UI-потока.
- [x] Во время работы показывается индикатор; устаревший результат не подменяет
  результат более нового запроса.
- [x] Предпросмотр и полное построение используют одну последовательную очередь.

GUI-тесты подтверждают, что запуск не блокирует UI, очередь не выполняет две
задачи одновременно и в предпросмотр попадает результат последнего запроса.

## Этап 3. Основа модели проекта

### 3.1. Версия формата и миграции

- [x] В JSON-проект добавлен `schema_version`; текущая версия — 2.
- [x] Файлы без версии распознаются как v0, строковые маршруты v1 мигрируют в
  структурированную v2; добавлены примеры всех версий, будущие версии отклоняются.
- [x] Тесты открывают и сохраняют каждую поддерживаемую входную версию.

### 3.2. Структурированные соединения

- [x] Строковое поле `route` заменено моделью шагов, компонентов и контактов.
- [x] Поддерживаемые параллельные группы и стрелки WireViz перенесены в
  структурированную модель без потерь при миграции.
- [x] Динамическое число шагов перенесено в структурированную модель без
  регрессии.
- [x] Добавлены стабильные внутренние ID; `X1`, `W1` и `F1` остались отображаемыми
  обозначениями.

Миграционные и GUI-тесты проверяют сохранность маршрутов, ID, стрелок,
параллельных групп и таблиц длиннее семи шагов.

### 3.3. Отмена и повтор действий

- [x] Добавлены `Undo/Redo` для полей, соединений, добавления, дублирования,
  удаления, шлейфов и переименования вместе со связанными маршрутами.
- [x] Единая история хранит снимки структурированной модели v2, восстанавливает
  dirty-состояние и очищается при установке другого документа.

GUI-тесты проверяют `Ctrl+Z`/`Ctrl+Y`, clean-checkpoint, поля, соединения,
добавление, удаление, переименование и Redo.
