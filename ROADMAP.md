# План развития WireWizardGUI

Пункты расположены в рекомендуемом порядке. К следующему крупному этапу лучше
переходить после выполнения критериев готовности предыдущего.

## Готово

- [x] Русский интерфейс, русские пользовательские сообщения и GUI-smoke-тесты.
- [x] Portable и устанавливаемые сборки для Windows и Ubuntu.
- [x] Автоматическая сборка релизных артефактов в GitHub Actions.
- [x] Надёжный разбор стрелок и параллельных групп WireViz в редакторе маршрутов.

## Этап 1. Исправления и защита данных

### 1.1. Надёжный разбор маршрутов — выполнено

- [x] Поддержаны стрелки WireViz `->`, `-->` и `<=>` без повреждения строки.
- [x] Параллельные группы сохраняются при открытии в табличном редакторе.
- [x] Сигнал в мастере шлейфа подключается один раз.

Импорт, редактирование и повторный экспорт покрыты доменными, GUI- и
интеграционными тестами с закреплённой версией WireViz.

### 1.2. Один канонический набор исходников

- Удалить зеркальные каталоги `domain/`, `services/`, `ui/` в корне или заменить
  их тонкими совместимыми обёртками.
- Оставить реализацию только в пакете `wirewizard_gui/`.

Критерий готовности: код приложения не дублируется, сборки и тесты используют
одни и те же модули.

### 1.3. Защита несохранённой работы

- Отслеживать состояние «проект изменён» и показывать `*` в заголовке окна.
- Запрашивать подтверждение перед созданием, открытием, импортом и закрытием.
- Добавить горячие клавиши `Ctrl+N`, `Ctrl+O`, `Ctrl+S`, `Ctrl+Shift+S`.
- Сохранять проект атомарно через временный файл и замену исходного.

Критерий готовности: пользователь не может молча потерять изменения, а ошибка
записи не повреждает существующий файл.

### 1.4. Безопасное переименование и удаление

- При переименовании компонента обновлять точные ссылки в соединениях.
- Перед удалением показывать зависимые строки и предлагать безопасный вариант.
- Не путать обозначения вроде `X1` и `X10`.

Критерий готовности: после операции валидатор не находит потерянных ссылок.

## Этап 2. Ежедневное удобство

### 2.1. Панель проблем

- Разделить ошибки и предупреждения.
- Показывать компонент и номер строки соединения.
- Переходить к проблемному элементу по двойному щелчку.
- Блокировать запуск WireViz при ошибках, но не при предупреждениях.

### 2.2. Улучшенный SVG-предпросмотр

- Масштабирование колёсиком, панорамирование и «Вписать в окно».
- Кнопки сохранения SVG и PNG.
- Связать выбранный элемент проекта с подсветкой на схеме, если это позволяет SVG.

### 2.3. Фоновое построение

- Выполнять WireViz вне UI-потока.
- Показывать индикатор работы и не подменять новый результат устаревшим.
- Оставить одну последовательную очередь рендера для безопасности WireViz.

Критерий готовности: интерфейс остаётся отзывчивым во время большой сборки схемы.

## Этап 3. Основа модели проекта

### 3.1. Версия формата и миграции

- Добавить `schema_version` в JSON-проект.
- Подготовить миграции и примеры файлов старых версий.
- Добавить тесты открытия и сохранения каждой поддерживаемой версии.

### 3.2. Структурированные соединения

- Заменить строковое поле `route` на модель шагов, компонентов и контактов.
- Перенести уже поддерживаемые параллельные группы и стрелки WireViz в
  структурированную модель без потерь при миграции.
- Перенести динамическое число шагов в структурированную модель без
  регрессии.
- Добавить стабильные внутренние ID, оставив `X1`, `W1` и `F1` отображаемыми
  обозначениями.

Это самый крупный этап; его следует начинать только после версионирования формата.

### 3.3. Отмена и повтор действий

- Добавить `Undo/Redo` для полей, соединений, добавления, удаления и переименования.
- Реализовывать после появления единого контроллера документа и структурированных связей.
